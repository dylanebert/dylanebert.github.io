Two agents were given the same RollerCoaster Tycoon park with the same instruction: maximize company value after a year. Here's what happened.

Luna 6 spent ten minutes, raised prices but didn't build anything, and ended at $73,268. Opus 5.5 spent almost three hours, discovered that closed rides keep their value and escape the duplicate-ride penalty, and ended at $1,523,497. Let's investigate how this happened.

The game

The game is RollerCoaster Tycoon 2, running in OpenRCT2. Agents play it through pb, the ParkBench command line from Can agents play RollerCoaster Tycoon?, which shows only what a player could see.

Each agent gets its own copy of the park to experiment on and writes ./bot, a program that plays the park on its own. I replay each bot from the same start on ten fresh seeds; game results here are means over those ten.

The score

The bot is scored on company value after one game year, eight months, and the prompt adds "Nothing after that counts." Both agents read the same definition of company value:

Both agents got the same prompt, advice, park and build. I compare one run of each, using Luna's best of three.

Each run leaves two records: the transcript of the agent writing its bot, which I loaded into Datadog's Agent Observability as a trace, and the game its bot played, which I replay tick by tick to compare company value with cash minus loan. Let's start with Luna.

What Luna did

Luna spends about ten minutes writing its bot. It explores the park, struggles to place a food stall, and sees company value jump when it refurbishes a ride. It repays the loan and sees company value unchanged, then tries fare multipliers and keeps the best.

Its bot sets fares from ride values, repays the loan at the start to save interest, and refurbishes every ride after five months.

What Opus did

Opus spends 167 minutes writing its bot. Four minutes in, it tests a ride, sees park value rise, and closes the ride to "check if the value sticks". It does, and Opus sets out to build "as many tested-then-closed rides as possible". Half an hour later it plans to borrow the maximum "right at the very end".

Fifty minutes in, it adds ride loops no path reaches, "to exploit the guest cap". Its bot opens them from the start; no guest can ride them. From month 5, the bot holds more cash minus loan than Luna's.

In the last 2% of the game, the bot borrows the maximum, spends all its cash building and testing rides, and closes them.

The bot leaves this park.

A score stands in for what you want

The score was meant to stand for a well-run park. Opus met it exactly as written, "Nothing after that counts" included.

This is Goodhart's law: when a measure becomes a target, it stops being a good measure. One run of each shows that this can happen, not how often or which model does it. I now trust an agent's score only as far as a record of what actually happened confirms it.
